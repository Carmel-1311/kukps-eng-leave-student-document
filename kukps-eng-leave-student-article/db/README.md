## นำเข้าเครื่องมือออนไลน์

เลือกตัวนำเข้า **MySQL SQL / DDL** แล้วใช้ไฟล์ `file_visual.sql` ของแต่ละโฟลเดอร์ เพื่อสร้าง diagram แยกฐาน หรือใช้ `db/file_visual.sql` สำหรับรวมทั้งสามชุด โดยไฟล์รวมเติมคำนำหน้าชื่อตาราง `db__`, `wh__`, `leave_com__` และปรับ REFERENCES ให้ตรงกัน เพื่อไม่ให้ตาราง `_prisma_migrations` ชนกัน ไฟล์แยกฐานคงชื่อจริงทั้งหมด ตรวจว่าเครื่องมือรองรับ MySQL DDL และ foreign key ก่อนนำเข้า ไฟล์เป็นโครงสร้างสำหรับดูภาพ ไม่ใช่ migration สำหรับรันกับฐานจริง

- `db/file_visual.sql`: ฐานธุรกรรม รวม `_prisma_migrations` เพื่อคงสคีมาครบ
- `wh/file_visual.sql`: warehouse ที่ติดตั้งจริง ใช้ `dw_*` ทั้ง 19 ตาราง
- `leave-com/file_visual.sql`: สคีมาจริงจาก Docker รวม `_prisma_migrations` เพื่อคงโครงสร้างครบ
- `schema-metadata.json` ในทั้งสามโฟลเดอร์: รายการตาราง คอลัมน์ ชนิดข้อมูล คีย์และ FK จาก metadata

ภาพอยู่ใน `../images/` เก็บ PNG ที่ใช้ในบทความ ได้แก่ `db-keys.png`, `wh-keys.png` และ `leave-com-full.png` พร้อม SVG แบบคอลัมน์ครบของทั้งสามฐานสำหรับขยายดู และ DOT ต้นฉบับของแผนภาพที่เก็บไว้ โดยตัดรูปแบบที่ไม่ถูกอ้างอิงออกแล้ว เส้นเชื่อมใช้ FK ภายในฐานเท่านั้น ไม่มีการสร้าง FK ข้ามระบบจากรหัสนิสิตหรือผู้สอน แผนภาพเป็นภาพโครงสร้างคีย์; ข้อกำหนด NULL, UNIQUE, DEFAULT และกฎ DELETE/UPDATE ให้อ่านจาก SQL เป็นหลัก

ฐาน leave-com ใช้ Docker ในเครื่องตามที่ผู้ใช้ยืนยัน ตรวจด้วย metadata และ SHOW CREATE TABLE แล้ว ไม่ได้อ่านข้อมูลแถวจริงหรือแก้ฐานข้อมูล ภาพและ SQL แทนร่างจาก Prisma เดิมด้วยโครงสร้างที่ตรวจพบจริง
