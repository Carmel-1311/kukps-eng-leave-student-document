# บทความระบบลานิสิต

## การปรับปรุง 18 ตุลาคม 2569

เพิ่ม functional requirements FR01–FR09 แยกตามบทบาทในบทที่ 4 และเกณฑ์ยอมรับใน `sections/08-appendix.tex` โดย `main.tex` รวมภาคผนวกท้ายเอกสารแล้ว เนื้อหาหลัก 6 หน้า ตามด้วยภาคผนวก 4 หน้า รวม `main.pdf` 10 หน้า พร้อม diagram db, wh และ leave-com ใน `images/` และรูปผู้เขียนในโฟลเดอร์เดียวกัน

ตรวจสคีมาฐาน db และ wh บน Railway แบบอ่านอย่างเดียวแล้ว ทั้งคู่เป็น MySQL 9.7.2 ฐานละ 19 ตาราง ส่วน leave-com ตรวจจาก MySQL 8.0.44 ใน Docker มี 5 ตาราง รวมตาราง migration ดูสถานะและไฟล์ SQL แบบรวม/แยกใน `db/README.md` การตรวจสคีมานี้ไม่ใช่การทดสอบการทำงานของแอปพลิเคชัน

คอมไพล์ทั้งบทความและภาคผนวกด้วย `scripts/build.ps1` ซึ่งรัน `main.tex` สองรอบ สำเนา PDF ในโฟลเดอร์หลักเป็นฉบับสำหรับเปิดอ่าน ส่วนไฟล์ระหว่างคอมไพล์อยู่ใน `build/` สำเนาภาคผนวกแยกเล่มเดิมสำรองไว้ใน `build/appendix-standalone-backup.*`

บทความ LaTeX ภาษาไทยและอังกฤษ จัดรูปแบบตาม `structure-ref/Template.pdf` และใช้โครงสร้างแยกไฟล์จาก `article/article` โดยเก็บโฟลเดอร์ต้นแบบไว้เดิม

## ไฟล์สำคัญ

- `main.tex`: จุดเริ่มต้นของบทความ
- `metadata.tex`: ชื่อเรื่อง ผู้เขียน และสังกัด
- `styles/article.tex`: รูปแบบ A4 สองคอลัมน์ คอลัมน์ละ 81 มม. ระยะห่าง 6 มม. Angsana New เนื้อหา 12 pt ระยะบรรทัด 16 pt
- `sections/`: เนื้อหาบทความแยกตามหัวข้อ
- `build/main.pdf`: ฉบับคอมไพล์สำหรับตรวจอ่าน (ไม่เก็บใน Git)
- `CAPTURE-REQUESTS.md`: รายการภาพและข้อมูลผู้เขียนที่ต้องจัดหาเพิ่ม
- `SOURCE-NOTES.md`: เส้นทางหลักฐานและข้อจำกัดของบทความ
- `build/original-root-sections/`: สำรองเนื้อหาที่มีอยู่ในโฟลเดอร์หลักก่อนแก้ไข

## คอมไพล์

ติดตั้ง MiKTeX หรือ TeX Live ที่มี XeLaTeX และฟอนต์ Angsana New จากนั้นเปิด PowerShell ที่โฟลเดอร์นี้:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/build.ps1
```

สคริปต์สร้าง `build/` และรัน XeLaTeX สองรอบเพื่อปรับเลขอ้างอิงรูปและตาราง โดยหยุดทันทีหากคอมไพล์ไม่ผ่าน หากเพิ่มภาพให้เก็บใน `images/` แล้วแทรกด้วย `includegraphics` และคำบรรยายใต้ภาพ ต้องตรวจจำนวนหน้าใหม่ทุกครั้ง Template ต้นฉบับกำหนดบทความทั่วไปไม่เกิน 4 หน้า แต่ฉบับปัจจุบันขยายเป็น 6 หน้าตามคำขอ โดยคงขนาดฟอนต์และรูปแบบเดิม

## การจัดเก็บใน Git และ VS Code

- เก็บต้นฉบับ `main.tex`, `metadata.tex`, `sections/`, `styles/`, รูปใช้งานใน `images/`, ฟอนต์ใน `fonts/`, เอกสารอ้างอิงใน `structure-ref/` และเอกสาร Markdown
- เก็บ `.vscode/settings.json`, `.vscode/extensions.json` และ `scripts/build.ps1` เพื่อให้ตั้งค่าและคอมไพล์เหมือนกัน โดยไม่ฝังพาธผู้ใช้หรือเขียนทับ PATH
- `build/` รวม PDF ไฟล์ประกอบคอมไพล์ ภาพตรวจหน้า และไฟล์สำรองภายในเครื่อง ไม่เก็บใน Git
- `article/` เป็นบทความต้นแบบในเครื่อง ไม่ถูก commit; หาก clone repo ใหม่ รูปแบบที่จำเป็นมีใน `styles/` แล้ว
- ไม่ ignore PDF ทั้งหมด เพื่อให้ `structure-ref/Template.pdf` และภาพ/เอกสารอ้างอิงยังเก็บใน Git ได้

เปิดโฟลเดอร์ repo ใน VS Code และติดตั้งส่วนขยายที่แนะนำ LaTeX Workshop จากนั้นใช้คำสั่ง **LaTeX Workshop: Build LaTeX project** หรือบันทึกไฟล์ LaTeX เพื่อคอมไพล์ PDF จะอยู่ที่ `build/main.pdf`

ต้องมี XeLaTeX ใน PATH และติดตั้ง Angsana New สคริปต์รองรับ PowerShell บน Windows; เครื่องอื่นคอมไพล์ด้วย XeLaTeX สองรอบจากโฟลเดอร์หลักและระบุ `-output-directory=build` หลังสร้างโฟลเดอร์ไว้แล้ว การจัดรูปแบบ LaTeX ด้วย `tex-fmt` เป็นตัวเลือกและต้องติดตั้งแยก ไม่จำเป็นต่อการคอมไพล์

ฟอนต์ที่มีอยู่ใน `fonts/` เก็บไว้ตามเดิม แต่รูปแบบปัจจุบันใช้ Angsana New จากระบบ ไม่ใช่ TH Sarabun ในโฟลเดอร์นี้
