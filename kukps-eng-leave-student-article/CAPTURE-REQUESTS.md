# ภาพและข้อมูลที่ต้องจัดหาเพิ่มเติม

ยังไม่ได้ capture หน้าจอในงานครั้งนี้ แผนภาพองค์ประกอบในบทความสร้างจากโครงสร้างโค้ด ไม่ใช่ภาพจากระบบที่ใช้งานจริง ภาพต่อไปนี้เป็นรายการเสนอให้เลือกใช้ ไม่จำเป็นต้องใส่ทั้งหมด โดยฉบับปัจจุบันขยายเป็น 6 หน้าตามคำขอ

| ลำดับ | ไฟล์ภาพที่เสนอ                | หน้าที่เปิดและสิ่งที่ต้องเห็น                                                        | คำบรรยายที่เสนอ                    |
| ----- | ----------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------- |
| 1     | `images/student-request.png`  | `/student/my-leave-request/new` แบบฟอร์มประเภทลา วันที่ เหตุผล และรายวิชา            | แบบฟอร์มยื่นคำขอลาของนิสิต         |
| 2     | `images/approval-flow.png`    | `/student/my-leave-request/[id]` ลำดับพิจารณาและสถานะ ใช้รหัสใบลาทดสอบจริงแทน `[id]` | การติดตามลำดับพิจารณาคำขอลา        |
| 3     | `images/advisor-review.png`   | `/user/approve-leave-request/as-advisor/[id]` ข้อมูลคำขอและปุ่มตัดสิน                | หน้าพิจารณาคำขอของอาจารย์ที่ปรึกษา |
| 4     | `images/student-report.png`   | `/student/report` ตัวกรองภาคการศึกษาและสรุปผล                                        | รายงานประวัติการลาของนิสิต         |
| 5     | `images/executive-report.png` | `/user/report/executive` ตัวกรองและสถิติที่มีข้อมูลยืนยัน                            | รายงานการลาสำหรับผู้บริหาร         |

## วิธีเตรียมภาพ

ใช้บัญชีและข้อมูลทดสอบที่ได้รับอนุญาต ปิดบังชื่อ รหัสนิสิต เบอร์โทร เหตุผลสุขภาพ และเอกสารหลักฐานที่ระบุตัวบุคคล ห้ามให้ token หรือข้อมูลลับปรากฏในภาพ บันทึก PNG เฉพาะส่วนที่เกี่ยวข้อง เลือกสถานะตัวอย่างที่ตรงกับคำอธิบาย และจดวันที่ สภาพแวดล้อม บทบาท และกรณีทดสอบไว้คู่กับภาพ

ภาพหนึ่งคอลัมน์กว้างไม่เกิน 81 มม. หากตัวหนังสืออ่านไม่ออกให้ crop เฉพาะส่วนสำคัญหรือใช้ภาพเต็มสองคอลัมน์ไม่เกิน 168 มม. คำบรรยายไม่เกินสองบรรทัดและไม่ขึ้นต้นด้วยคำว่า “แสดง” ตรวจจำนวนหน้าหลังเพิ่มภาพทุกครั้ง

## ข้อมูลที่ยังต้องยืนยัน

- โทรศัพท์และอีเมลติดต่อของผู้เขียนสำหรับส่วนหัวบทความ
- รูปผู้เขียนแต่ละคนขนาด 2 × 2 ซม. พร้อมประวัติย่อและงานวิจัยที่สนใจตาม Template
- หลักฐานผลทดสอบและผลประเมินผู้ใช้ หากต้องการเปลี่ยนหัวข้อผลตรวจโค้ดเป็นผลทดลอง

## ภาพเพิ่มเติมสำหรับ ระบบข้อมูลสนับสนุน และ warehouse

| ไฟล์ภาพที่เสนอ                  | แหล่งภาพและสิ่งที่ต้องเห็น                                                                                           | คำบรรยายที่เสนอ                                |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `images/leave-com-subjects.png` | เปิดหน้า `/` ของเว็บ ระบบข้อมูลสนับสนุน แล้วเลือกส่วนรายวิชา/หมู่เรียน ต้องเห็นวิชา ตอนเรียน และผู้สอนจากข้อมูลทดสอบ | การจัดการรายวิชาและผู้สอนใน ระบบข้อมูลสนับสนุน |
| `images/leave-com-advisors.png` | หน้าเดียวกัน เลือกส่วนที่ปรึกษา–นิสิต แสดงความสัมพันธ์ตัวอย่างที่ปิดบังข้อมูลบุคคลแล้ว                               | การจัดการความสัมพันธ์ที่ปรึกษาและนิสิต         |
| `images/leave-com-import.png`   | เลือกหน้าต่างนำเข้า Excel เห็นชนิดข้อมูลและโหมดเพิ่ม/แทนที่ โดยไม่ต้องกดนำเข้าจริงเพื่อถ่ายภาพ                       | การนำเข้าข้อมูลอ้างอิงจาก Excel                |
| `images/warehouse-report.png`   | หน้ารายงานระบบใบลาที่เลือกปีและเทอมไว้ เห็นสถิติกับเวลาการโหลดสำเร็จล่าสุด หากองค์ประกอบนี้ปรากฏในรุ่นที่ใช้งาน      | รายงานจากคลังข้อมูลตามขอบเขตผู้ใช้             |

Warehouse ไม่มีหน้าจัดการ ETL โดยเฉพาะที่ยืนยันจากการตรวจครั้งนี้ หากต้องการภาพผลรันให้ใช้ผลจากฐานทดสอบที่รันและตรวจจริง พร้อมระบุวันที่ batch และจำนวนแถว ห้ามใช้ภาพตัวอย่างแทนผลทดลอง หรือเปิดเผย connection string และข้อมูลส่วนบุคคล

บทความปัจจุบัน 6 หน้าแล้ว การใส่ภาพเพิ่มต้องตัดหรือแทนที่เนื้อหาบางส่วน และตรวจรูปแบบใหม่ เลือกภาพที่จำเป็นและตรวจจำนวนหน้าตามเกณฑ์ฉบับที่จะส่ง
